# Pairings Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a read-only Pairings dashboard page that snapshots every current-round Spicerack pairing once per round and ranks matchups by macro-archetype uniqueness.

**Architecture:** Add a dedicated Convex `pairings` table and capture rows from the existing new-round path. Keep ranking logic in a framework-neutral library so it can be tested directly and reused by the Convex query. Render `/dashboard/pairings` as a dense operational table beside the existing dashboard pages.

**Tech Stack:** Next.js App Router, React, Convex, TypeScript, Vitest, Tailwind, existing shadcn-style UI components.

---

## File Map

- Modify `convex/schema.ts`: register the `pairings` table and indexes.
- Modify `convex/validators.ts`: add pairing validators and returned ranked-pairing shape.
- Create `lib/pairing-rankings.ts`: macro normalization, known-deck checks, score calculation, stable sorting.
- Create `lib/__tests__/pairing-rankings.test.ts`: red-green tests for ranking and unknown deck behavior.
- Create `convex/lib/pairings.ts`: parse current-round matches and insert idempotent pairing snapshots.
- Create `convex/pairings.ts`: authenticated query for current user's current-round ranked pairings.
- Modify `convex/lib/spicerack/rounds.ts`: call snapshot creation exactly when a new round is handled.
- Modify `app/dashboard/layout.tsx`: add Pairings sidebar navigation.
- Create `app/dashboard/pairings/page.tsx`: read-only pairings page.

## Visual Direction

- Visual thesis: a quiet tournament-operations table with just enough hierarchy to make the best matchups easy to scan under time pressure.
- Content plan: round status and count at the top, then a single dense ranking table with compact empty states.
- Interaction thesis: no custom animation; rely on existing sidebar active state and table row hover/focus states.

```ts
export type PairingRankingPlayer = {
  name: string;
  deckName: string;
};

export type PairingRankingInput = {
  tableNumber?: number;
  player1Data?: PairingRankingPlayer;
  player2Data?: PairingRankingPlayer;
};

export type RankedPairing<TPairing extends PairingRankingInput> = TPairing & {
  rank: number;
  player1MacroArchetype?: string;
  player2MacroArchetype?: string;
  uniquenessScore?: number;
  hasKnownDecks: boolean;
};

export function rankPairingsByUniqueness<TPairing extends PairingRankingInput>(
  pairings: TPairing[],
  tournamentPlayers: PairingRankingPlayer[],
): RankedPairing<TPairing>[];
```
